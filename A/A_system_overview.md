# A 모듈 시스템 개요 및 한계

**작성일:** 2026-06-07
**대상:** A+C 통합 시스템 사용 가이드 + 한계 분석

## 1. 시스템 한 줄 요약

```
CCTV 영상 → A 파이프라인 (전처리 + 호모그래피 캘리브레이션)
         → JSON 데이터 추출
         → C 룰 적용
         → 의심 차량 시각화 영상 출력
```

**검출 대상**: 차선 표류 (lane_weaving), 급차선 변경 (lane_change), 짧은 차간거리 (tailgating)

## 2. 영상 처리 흐름 (사용자 관점)

```
1. CCTV 영상 준비 (mp4)
    ↓
2. 영상에 대해 1회 캘리브레이션:
   - road_only 생성 (차량 제거 배경)
   - 격자 이미지 보기
   - 도로 위 4점 수동 선택 ← 사용자 입력 필요
   - 호모그래피 행렬 자동 계산
   - BEV (탑뷰) 검증
    ↓
3. YOLO + ByteTrack 자동 처리
   - 차량 검출 + 추적 (ID 부여)
    ↓
4. 호모그래피 적용
   - 픽셀 좌표 → 미터 좌표
   - 차로 번호, 차로 중심 이탈, 속도 계산
    ↓
5. JSON v1.1 출력 (A 결과)
    ↓
6. C 룰 적용
   - 차선 표류, 차선 변경, 차간거리 판정
    ↓
7. 시각화 영상 출력
   - 의심 차량: 빨간 박스 + 사유 자막
   - 정상 차량: 초록 박스
```

## 3. 시스템의 한계

### 3.1 한계 1: 호모그래피 4점 수동 선택 필수

```
[현재 시스템]
- 영상마다 사람이 도로 위 4점 직접 선택
- 격자 이미지 보고 (x, y) 좌표 입력
- 영상당 10~20분 소요

[이상적]
- 영상 업로드만 하면 자동 처리
- 4점 자동 선택
- 즉시 결과
```

**원인**: 도로 위 4점의 실제 거리 (예: 50m × 17.5m)는 환경마다 달라서 자동화 어려움. 사람이 도로 마킹 보고 판단해야 정확.

**의미**: 시스템이 "완전 자동" 아님. 영상마다 캘리브레이션 단계 필요.

### 3.2 한계 2: 카메라 시점 의존성

```
[적합한 영상]
- 비스듬한 각도 (CCTV 일반)
- 차량 측면 + 위 부분 보임
- YOLO가 차량 잘 검출

[부적합 영상]
- 거의 수직 (위에서 내려다보는 각도) ← v03 사례
- YOLO가 차량 못 잡음 → 처리 불가능
```

**의미**: 모든 CCTV 영상에 적용 가능 X. 카메라 각도 적당해야 함.

### 3.3 한계 3: 호모그래피 영역 제한

```
[현재]
- 4점으로 정의한 영역 안에서만 분석
- 영역 밖 차량 = 검출은 되지만 위치 부정확
- 영역 크기 보통 50m × 17.5m

[효과]
- 검출률 약 24% (영역 안 차량만)
- 영역 밖 차량 분석 제외
```

### 3.4 한계 4: 실제 환경 정량 평가 불가

```
[CARLA 시뮬레이션]
- GT (정답) 있음
- 룰 정확도: P/R/F1 = 1.00 (100%)

[실제 CCTV]
- GT 없음
- 의심 비율 50%인 게 정확한지 잘못된지 모름
- 임계값 튜닝으로 부분 개선 가능
```

**의미**: 실제 한국 도로에서 시스템이 "얼마나 정확한지" 숫자로 못 말함.

### 3.5 한계 5: 한국 도로 특성과의 격차

```
[CARLA 기준 임계값]
- tail_gap: 5m (앞차와 5m 이내면 의심)
- lane_change: 1회 (1번 차선 변경 = 의심)
- weaving_std: 0.30m

[한국 도시 도로 현실]
- 차간거리 5m 이내 매우 일상적
- 다차로 도로에서 차로 변경 빈번
- → 기본 임계값 적용 시 false positive 폭발

[해결]
- 극엄격 임계값으로 조정 (tail_gap 1.5m, lane_change 5회 등)
- 그래도 의심 비율 50% 수준
- 완전 해결 못 함
```

### 3.6 한계 6: 속도 룰 비활성

```
- 4개 룰 설계했으나 속도 룰 비활성
- 이유: CARLA 속도 데이터로 검증 어려움
- → 빠른 차량은 잡지 못함
```

## 4. 시스템 강점

이 한계들에도 불구하고 잘 작동하는 부분:

- ✅ **CARLA 통제 환경에서 활성 룰 3개 정확도 100%** (P/R/F1 = 1.00)
- ✅ **A → C 데이터 인터페이스 안정** (JSON v1.1 스키마)
- ✅ **임계값 동적 조정 가능** (`thresholds` 파라미터)
- ✅ **5개 CCTV + 5개 CARLA = 10개 영상 처리 검증**
- ✅ **한국 도로 적용 시 임계값 튜닝 효과 확인** (4가지 비교)

## 5. 향후 개선 방향

### 5.1 자동 호모그래피 캘리브레이션
- 도로 마킹 자동 검출 → 4점 자동 선택
- 사람 개입 없이 영상만으로 처리

### 5.2 한국 도로 GT 데이터 확보
- 실제 영상에 위험 차량 라벨링
- CCTV에서도 정량 평가 가능

### 5.3 A 시스템 시계열 평활화
- lane_id, lateral_offset 잡음 감소
- Kalman Filter 적용
- false positive 줄임

### 5.4 속도 룰 활성화
- A 속도 추정 정밀화
- 4개 룰 완전 시스템

### 5.5 자동 임계값 학습
- 영상 환경 자동 판단 (정체 vs 흐름)
- 환경별 적절한 임계값 자동 적용

## 6. 시스템 사용 요약

### 사용 가능한 경우

✅ CCTV 영상 (비스듬한 각도)
✅ CARLA 시뮬레이션 영상
✅ 도로 마킹 보이는 영상
✅ 차량 크기 적당 (YOLO 검출 가능)

### 사용 어려운 경우

❌ 카메라 거의 수직 시점
❌ 도로 마킹 안 보임
❌ 차량 너무 작거나 가려짐
❌ 야간/악천후 (YOLO 정확도 ↓)

## 7. 핵심 메시지

### 시스템 의의

- **알고리즘 정확성 입증**: CARLA 통제 환경에서 100% 정확
- **솔직한 한계 인식**: 자동화 부족, 실제 환경 평가 어려움
- **명확한 향후 방향**: 자동 캘리브레이션, GT 확보, 평활화 등

### 실제 환경 적용 시 고려사항

- 영상마다 캘리브레이션 단계 필요 (자동 X)
- 카메라 시점 사전 확인 필요
- 한국 도로 특성에 맞는 임계값 튜닝 필요
- 정량 평가는 GT 있는 환경에서만 가능
